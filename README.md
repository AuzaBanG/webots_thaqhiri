# Padoru Webots Drone

ROS 2 and Webots simulation for a Mavic 2 PRO drone, with an optional
ArduPilot SITL container for flight-controller integration.

The repository contains:

- `src/padoru_webots`: the ROS 2 package that starts Webots, publishes the
  robot description and TF frames, and provides keyboard teleoperation.
- `webots_world`: the Webots world and drone/proximity-sensor prototypes.
- `ardupilot_dev_docker`: the ArduPilot development-container definitions.
- `docker-compose.yml`: the two-container development environment.

## Requirements

- Linux with Docker Engine and the Docker Compose plugin
- An X11 session (`DISPLAY` must be set)
- NVIDIA Container Toolkit and a working GPU driver
- A ROS 2 Jazzy/Webots-capable machine if running without Docker
- An ArduPilot checkout at `../ardu_ws` when using the `ardupilot_sitl`
  service (the compose file mounts it at `/home/ardupilot/ros_ws`)

The Webots image is based on `osrf/ros:jazzy-desktop-full` and installs Webots
R2025a. The ArduPilot image uses its own ROS environment, so source the
environment shown in the container when working on that side.

## Start the development environment

Allow the container to connect to the display, then build and start both
services:

```bash
xhost +local:docker
docker compose build
docker compose up -d
```

Open a shell in the Webots container:

```bash
docker compose exec padoru_webots_jazzy bash
```

When finished, stop the services and optionally remove the containers:

```bash
docker compose down
xhost -local:docker
```

> **GPU note:** `docker-compose.yml` requests all NVIDIA GPUs and `/dev/dri`.
> If the image cannot start, check the NVIDIA Container Toolkit installation
> and verify that `nvidia-smi` works on the host.

## Build the ROS 2 workspace

Run these commands inside `padoru_webots_jazzy`:

```bash
source /opt/ros/jazzy/setup.bash
cd /home/ubuntu/ros_ws
rosdep update
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

The `install` directory is generated by `colcon` and should be rebuilt after
changing package metadata or adding installed resources.

## Run Webots

Start the default world and drone controller:

```bash
source /home/ubuntu/ros_ws/install/setup.bash
ros2 launch padoru_webots drone_launch.py
```

To enable the optional RTAB-Map launch path:

```bash
ros2 launch padoru_webots drone_launch.py rtabmap:=True
```

The launch file uses `src/padoru_webots/webots_world/worlds/test.wbt`, loads
`drone_padoru2.urdf`, and starts the `Mavic 2 PRO` Webots controller.

## Teleoperate the drone

With Webots running, open a second shell:

```bash
docker compose exec padoru_webots_jazzy bash
source /opt/ros/jazzy/setup.bash
source /home/ubuntu/ros_ws/install/setup.bash
ros2 run padoru_webots teleop_drone
```

The teleoperation node publishes `geometry_msgs/msg/Twist` messages on
`cmd_pos`.

| Key | Action |
| --- | --- |
| `i`, `u`, `o` | Move forward and diagonally |
| `j`, `l` | Move left or right |
| `m`, `,`, `.` | Move backward and diagonally |
| `t`, `b` | Move up or down |
| `y`, `n` | Yaw left or right |
| Any other key | Publish a stop command |
| `Ctrl-C` | Exit |

The node expects a terminal with a US keyboard layout and an attached
interactive stdin.

## Run ArduPilot SITL

Start the ArduPilot service and open a shell:

```bash
docker compose up -d ardupilot_sitl
docker compose exec ardupilot_sitl bash
```

Inside the ArduPilot container, install dependencies and build the mounted
workspace:

```bash
source /opt/ros/jazzy/setup.bash
cd /home/ardupilot/ros_ws
sudo apt update
pip install -U --ignore-installed numpy MAVProxy
rosdep update
rosdep install --rosdistro "$ROS_DISTRO" \
  --from-paths src --ignore-src --skip-keys microxrcedds_agent -y
git config --global --add safe.directory "*"
colcon build --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
```

Run the DDS UDP SITL launch:

```bash
ros2 launch ardupilot_sitl sitl_dds_udp.launch.py \
  transport:=udp4 \
  synthetic_clock:=True \
  wipe:=False \
  model:=webots-python \
  speedup:=1 \
  slave:=0 \
  instance:=0 \
  defaults:=$(pwd)/thaiquiri.parm,$(ros2 pkg prefix ardupilot_sitl)/share/ardupilot_sitl/config/default_params/dds_udp.parm \
  sim_address:=172.18.0.2 \
  master:=tcp:127.0.0.1:5760 \
  sitl:=127.0.0.1:5501
```

The services share the `drone_net` Docker network. The compose file exposes
MAVLink UDP port `14550` and TCP port `5760` on the host.

## Tests and diagnostics

Run the package tests from the Webots container:

```bash
cd /home/ubuntu/ros_ws
source /opt/ros/jazzy/setup.bash
colcon test --packages-select padoru_webots
colcon test-result --all --verbose
```

Useful checks:

```bash
ros2 topic list
ros2 topic echo /cmd_pos
docker compose ps
docker compose logs -f padoru_webots_jazzy
```

If ROS nodes cannot discover one another, confirm that both containers use
`ROS_DOMAIN_ID=42` and that `ROS_LOCALHOST_ONLY=0`. If Webots does not display,
check `DISPLAY`, the X11 permission command, and the GPU prerequisites above.
